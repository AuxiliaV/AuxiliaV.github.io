HR Policy RAG Assistant

Project Overview

The HR Policy RAG Assistant is a conversational question-answering application designed to retrieve information from company policy documents and generate concise answers with citations.

The project uses three sample HR policy documents created for a fictional company, Acme Corp. Instead of relying only on the language model's general knowledge, the assistant retrieves relevant sections from the provided documents before generating an answer.

Objective

The objective was to build an end-to-end conversational RAG application that could answer HR policy questions using information from a controlled set of documents.

  • Retrieve relevant information from HR policy documents.
  • Generate concise answers based on retrieved content.
  • Include policy and page references with answers.
  • Support follow-up questions using conversation history.
  • Return a clear response when information is not available in the documents.

Policy Documents

The assistant works with three sample policy documents created for the fictional Acme Corp environment.

Acme Leave Policy Leave entitlement, sick leave, parental leave, bereavement leave and leave requests.
Acme Remote Work Policy Hybrid and remote work eligibility, core hours, home-office support and remote work requirements.
Acme Travel & Expense Policy Expense submission, approvals, travel allowances, mileage and reimbursement rules.
Note: Acme Corp and the policy documents used in this project are fictional/sample data created for demonstration and learning purposes.

Document Loading & Preprocessing

The PDF policy documents are loaded using LangChain's PyPDFLoader. During preprocessing, the document metadata is enriched so that retrieved information can later be associated with the original policy and page number.

Cleaning

  • Removed unwanted footer content.
  • Removed internal-use-only footer text.
  • Cleaned unnecessary line formatting.
  • Added policy name as source metadata.
  • Added page number metadata for citations.

Document Chunking

After preprocessing, the documents are split into smaller sections using LangChain's RecursiveCharacterTextSplitter.

Chunk Size 600 characters
Chunk Overlap 100 characters
Splitter RecursiveCharacterTextSplitter
Metadata Policy name + page number

The metadata is copied to the resulting chunks, allowing retrieved chunks to retain their source information.

Embeddings & Vector Database

The document chunks are converted into vector representations using OpenAI's text-embedding-3-small embedding model.

These embeddings are stored in a FAISS vector store. When a user asks a question, the application performs semantic retrieval to find relevant document chunks.

Embedding Model text-embedding-3-small
Vector Store FAISS
Retriever Similarity-based retrieval
Retrieved Chunks Top 4

RAG Question-Answering Workflow

The assistant follows a Retrieval-Augmented Generation workflow in which relevant policy content is retrieved before the language model generates the answer.

User Question Employee asks an HR policy question
↓
Semantic Retrieval Relevant chunks are retrieved from FAISS
↓
Context Construction Retrieved content is passed as context
↓
ChatOpenAI Generates an answer from the provided sources
↓
Answer + Citation Response includes policy and page reference

Answer Generation

Retrieved document chunks are combined into a context and passed to a ChatOpenAI model through a ChatPromptTemplate.

The prompt instructs the assistant to answer using only the provided sources, mention relevant conditions or exceptions, keep the response short, and include the corresponding policy citation.

LLM gpt-4o-mini
Temperature 0
Prompt Framework ChatPromptTemplate
Response Answer with source citation

Citation-Based Responses

Each retrieved document retains its policy name and page metadata. This information is used to generate citations such as: [Acme Leave Policy, p.2]

This makes the generated answer easier to trace back to the relevant policy document.

Conversational Follow-up Questions

The application also supports follow-up questions. Previous question-and-answer pairs are stored in the application's chat history.

When a follow-up question depends on previous conversation context, the latest question is rewritten into a standalone question before retrieval.

Chat History Previous questions and answers
↓
Question Rewriting Latest question becomes standalone
↓
FAISS Retrieval Relevant policy chunks are retrieved
↓
Answer Generation Answer is generated with citation

Application Demo

The application was tested through a Gradio interface with questions covering different areas of the sample HR policies.

Leave Policy: The assistant retrieves the annual leave carryover rule and provides the corresponding policy citation.

Remote Work Policy: The assistant identifies the minimum office days and the designated core in-office days.

Policy Condition: The assistant distinguishes between hybrid and fully remote employee eligibility for the internet allowance.

Unavailable Information: When the requested information is not contained in the provided documents, the assistant returns the configured fallback response.

Limitations & Future Improvements

This project is a learning and portfolio implementation using a small set of fictional policy documents. It demonstrates the RAG workflow but is not intended to represent a production HR system.

Current Limitations

  • The policy dataset is limited to three sample documents.
  • The FAISS index is created when the RAG module starts.
  • Conversation history is maintained in application memory.
  • The application does not connect to a real HR management system or employee database.
  • Authentication and role-based access control are not implemented.

Possible Future Improvements

  • Add persistent vector-store storage and indexing.
  • Add authentication and employee-specific access control.
  • Connect the assistant to approved HR APIs or backend services.
  • Add more HR policy documents and document management.
  • Add evaluation datasets for retrieval and answer quality.
  • Improve the user interface and conversation management.

Key Takeaway

This project provided practical experience in building an end-to-end conversational RAG application, including PDF processing, document chunking, embeddings, vector retrieval, citation-aware answer generation, conversational question rewriting, and Gradio-based application development.
